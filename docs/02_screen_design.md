## 3. 認証画面

LPヘッダーは固定表示とし、スクロール中もログインと無料登録の導線を常に利用できる。
スマホ、タブレット、PCのいずれでも同じナビゲーション項目を表示し、幅が足りない場合は横スクロールで操作する。
ログイン後の共通ヘッダーも固定表示とし、どの画面でもナビゲーションとログアウトを常時操作できる。
ログイン後の本文開始位置は、実際のヘッダー高さに合わせて自動調整する。
LP内リンクの遷移先は固定ヘッダーの実測高さを基準に余白を取り、見出しや登録フォームがヘッダー下に隠れないようにする。

### 3.1 ログイン

| 項目   | 内容                                                    |
| ------ | ------------------------------------------------------- |
| 入力   | メールアドレス、パスワード                              |
| API    | `POST /api/auth/login`                                  |
| 成功時 | JWTとユーザー情報を保存し、ロールに応じた初期画面へ遷移 |
| 失敗時 | エラーメッセージを表示                                  |

デモログイン導線は開発環境のみ表示し、本番UIには表示しない。

### 3.2 求職者登録

| 項目       | 内容                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 入力       | 氏名、メールアドレス、電話番号、職種、パスワード、パスワード確認、プライバシーポリシー同意 |
| API        | `POST /api/auth/register`                                                                  |
| 登録ロール | 常に `freelancer`                                                                          |
| 同時登録   | `freelancerProfile` と `privacyPolicyConsent`                                              |

## 4. プロフィール画面

プロフィールは4ステップのウィザードで入力する。

| ステップ          | 内容                                                                   | 主な保存API                                         |
| ----------------- | ---------------------------------------------------------------------- | --------------------------------------------------- |
| 1. 基本情報       | 氏名、メールアドレス、電話番号、職種                                   | `PUT /api/profile/me`                               |
| 2. スキル         | 言語、DB、フレームワーク、クラウド、その他、経験年数                   | `PUT /api/profile/me`                               |
| 3. 条件・レジュメ | 希望単価、稼働開始日、稼働率、リモート条件、稼働状況、レジュメメタ情報 | `PUT /api/profile/me`, `POST /api/resumes`          |
| 4. 面談候補       | 面談候補日時、誓約同意                                                 | `POST /api/meeting-requests`, `PUT /api/profile/me` |

## 5. 案件検索画面

### 5.1 検索条件

- キーワード
- スキル
- 単価
- リモート条件
- 商流

### 5.2 表示制御

求職者のプロフィール要件が未完了の場合、案件一覧ではなくロックパネルを表示する。API側でも同様に、要件未完了時は `403 PROFILE_REQUIREMENTS_INCOMPLETE` を返す。
プロフィール要件を満たした求職者は、初回面談の完了前でも案件応募できる。初回面談の完了条件は、案件ごとの面談候補登録にのみ適用する。

## 6. 営業管理画面

### 6.1 案件登録

| 項目           | 内容                               |
| -------------- | ---------------------------------- |
| 案件名         | 必須                               |
| クライアント名 | 任意。未入力時は「未設定」扱い     |
| 概要           | 任意                               |
| 必須スキル     | 複数                               |
| 歓迎スキル     | 複数                               |
| 単価           | 最小・最大                         |
| マージン率     | 0〜100                             |
| 商流           | エンド直、1次請け、2次請け、その他 |
| リモート条件   | フルリモート、一部リモート、常駐   |
| 優先表示       | ON/OFF                             |

### 6.2 応募管理

応募ステータスは以下の4つ。

| ステータス | DB値              |
| ---------- | ----------------- |
| 選考中     | `screening`       |
| 面談待ち   | `meeting_pending` |
| 成約       | `contracted`      |
| 見送り     | `rejected`        |

## 7. スカウト画面

営業担当者はフリーランス候補者をスキル、稼働状況、リモート条件で絞り込み、候補者にスカウトメッセージを送信できる。スカウトは `messageType = scout` のメッセージとして保存される。

## 9. 匿名スキルシート画面

- 氏名をマスク表示する。
- 主要スキル、経験年数、希望単価、稼働条件、レジュメ情報を表示する。
- 共有URLコピーは提供しない。
- ブラウザ印刷ではなく、匿名スキルシート専用に整形したPDFを出力する。

## 10. レスポンシブ方針

- スマホ、タブレット、PCで画面構成と主要操作を分けない。
- ヘッダー、ナビゲーション、カード、フォームは同じ情報量を保ち、幅が足りない場合は折り返しまたは横スクロールで対応する。
- 端末幅によって機能を隠さない。表示密度のみ調整する。
- 案件カードは端末別の折りたたみUIを使わず、同じカード構成で表示する。
- Windows / macOS / iOS / Android の標準UI差を抑えるため、フォーム部品は共通のフォント、タップサイズ、フォーカスリング、select矢印を使う。
- 固定ヘッダー、通知、モーダル、トーストは safe-area を考慮し、ノッチやモバイルブラウザの上下バーで内容が隠れないようにする。
- LPの数値や単価は文言を増やさず、等幅数字とカード内の強調エリアでベネフィットが伝わるようにする。
- モーダル表示中は背景コンテンツを固定し、モーダル内部だけをスクロール対象にする。
